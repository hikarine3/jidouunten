# 日本向け自動運転・運転支援車selector 市場・競合調査

確認日: 2026-09-07

## 結論

日本の購入検討者には自動運転への関心がある一方、安全性と価格への不安も強い。既存ページは、
レベル解説、世界の車種一覧、個別車種の中古車相場、メーカー別の機能説明に分断されている。
`jidouunten.jp` の勝ち筋は、記事量や網羅車種数ではなく、**日本で現在選べる販売単位を、実際に
使える道路・速度・監視・必要装備まで同じ形式で比較し、一次情報と確認日へ戻れること**に置く。

以下では、外部ページで確認できた内容を「観測」、そこからの事業判断を「推論」として分ける。
検索ボリュームや市場規模の推計は行っていない。

## 需要の根拠（観測）

- JAMAの2025年度調査では、四輪車保有世帯6,600件のうち、望む自動運転技術はLevel 3が20%、
  Level 4が10%、Level 5が13%で、Level 3以上は計43%。「望まない」は28%だった。
- 同じ6,600件では、Level 3車を主に運転する車として購入したい人が35%、別の車として購入したい
  人が7%で、購入意向は計42%。Level 4と5の同合計はいずれも34%だった。
- 自動運転車を活用したいと回答した四輪車保有世帯4,773件では、用途は個人の趣味・レジャー48%、
  家族とのレジャー46%、日常の買物・用足し45%が上位だった。
- 自動運転車に関心がない四輪車保有世帯2,086件では、理由の上位は安全面の不安52%、
  販売価格が高い39%。別設問の四輪車保有世帯6,600件では、期待することは安全性向上33%、
  利便性向上27%、渋滞緩和20%だった。
- NASVAの2024〜2025年度予防安全性能アセスメントは、衝突被害軽減ブレーキ、車線逸脱抑制、
  高機能前照灯を車種別に試験・採点する。つまり購入者が確認すべき「公的な試験結果」という
  レベル分類とは別の比較軸が実在する。

注意: JAMAの回答は意向であり、selectorの検索需要、利用数、成約数を示すものではない。

補足観測:

- 自動運転ラボは更新日を明記するが、確認した一覧は日本で買える乗用車だけでなく、海外車、
  移動サービス、実証車を同じ記事内で扱う。
- カーセンサーは、アコードの標準仕様とハンズオフ対応グレードを分け、中古車価格帯と在庫導線を
  提示する。購入に近いが、複数メーカーのODDを同じ項目で比べるページではない。
- グーネットの確認記事はLevel 1〜2を運転支援と説明する一方、2020年時点の車種状況を残している。

- 日産はプロパイロット2.0を自動運転装置ではないと明記し、前方注視、即時操作可能であること、
  対面通行路、トンネル、急カーブ、料金所・合流地点等ではハンズオフ不可と説明する。
- HondaのLevel 3ページはシステムが周辺監視と操作を担う条件、および領域外で運転交代が必要なことを
  示し、同時に対象モデルが2022年1月終了モデルであることも明記する。

## 市場機会と勝ち筋（推論）

追加確認（同日）: カーセンサーの実検索画面 https://www.carsensor.net/usedcar/ には、
メーカー・モデル/グレード・年式・価格に加え、アダプティブクルーズコントロール、
レーンキープアシスト、パーキングアシスト等の絞り込みがある。グーネットも
https://www.goo-net.com/usedcar/ で在庫検索を提供する。上表の記事だけを根拠に
両サービス全体に比較・検索がないとは判断しない。今回確認したカーセンサーの検索項目では、
SAEレベル・ハンズオフの速度域・道路区間・引継ぎ条件の組合せは確認できなかった。
差別化仮説は装備有無の検索ではなく、これらの条件と一次情報を横断して候補を判断できる点にある。

1. **「レベル」から「自分の道で使えるか」へ翻訳する。** JAMAで需要の大きいレジャー・買物を
   入口にし、高速道路、渋滞、一般道、速度域、天候、監視方式で候補を減らす。
2. **販売単位で比較する。** 車種名だけでなく、モデル年、グレード、必須オプション、契約、
   新車・中古・販売終了を分ける。カーセンサーの購入近接性とメーカー情報の正確性を接続できる。
3. **機能名ではなく責任と制限を先に出す。** Level 2の常時監視、Level 3の引継ぎ要求、ハンズオフ
   不可区間をカードと比較表に固定表示し、安全不安に対して誇張ではなく判断材料を返す。
4. **根拠と鮮度を内部データ機能にする。** 各値にメーカー・取扱説明書等のURL、対象市場、確認日、
   `unknown` / `stale` を持たせる。更新履歴が蓄積し、記事の一時的な網羅性とは異なる堀になる。
5. **公的安全評価は自動化レベルと分離する。** NASVA結果へ案内しても、「高レベルだから安全」とは
   表現しない。Level/ODD比較と予防安全試験を別軸で扱うこと自体が信頼差になる。

現時点では、SEO流入や送客収益の優位は未検証。競合に欄がないことだけでは需要を証明しないため、
selector内行動と遷移を計測してから拡張する。

## 推奨Sprint順位（推論）

GitHub ProjectのReadyキューが実行順の正本であり、以下は次回選定時の市場調査上の推奨順位。

| 順位 | 利用者向け成果 | 最小範囲 | 判定 |
|---:|---|---|---|
| 1 | Level-first selector | 日本向け販売単位6件以上、Level/道路/ハンズオフ/販売状態、2台比較、内部の根拠・確認日 | 絞込と比較が実ブラウザで完遂できる |
| 2 | 用途質問から候補提示 | 高速レジャー、渋滞、日常買物等を既存比較軸へ変換 | ガイド開始から候補詳細まで遷移できる |
| 3 | 鮮度・販売状態の可視化 | 期限切れ検知、`stale`/`unknown`、差分レビュー | 期限内確認率と未確認件数を取得できる |
| 4 | 送客と計測 | 公式確認と販売先を分離し、比較完了後に提示 | 誤クリックを除いた外部遷移を計測できる |
| 5 | 選択意図型の解説 | 実測された離脱・疑問に対応し、selectorへ戻す | 記事PVではなくselector復帰率で評価できる |

計測イベントの実装はSprint 1の受入に含める。計測基盤だけを独立した価値Sprintにはしない。

## KPIと判断方法（推論）

初回公開後は、検索順位や架空の検索量ではなく、同意済みの実イベントで基準値を作る。

| KPI | 定義 | 何を判断するか |
|---|---|---|
| selector開始率 | selector開始セッション / selector到達セッション | 入口と価値説明が通じるか |
| 絞込完了率 | 1件以上の候補表示まで到達 / selector開始 | 質問・フィルタが答えにつながるか |
| 比較開始率 | 2台選択 / 候補表示到達 | 比較対象と操作が理解できるか |
| 比較完了率 | 比較表の主要条件を表示 / 比較開始 | 横断比較が実際に完遂されるか |
| 根拠確認率 | 公式根拠クリック / 車両詳細表示 | 信頼情報が利用されるか |
| 販売先遷移率 | 販売先クリック / 比較完了 | 意思決定が次の行動につながるか |
| 期限内確認率 | 確認期限内の公開レコード / 公開レコード | データ品質が維持できるか |
| selector復帰率 | 解説・ニュースからselectorへ遷移 / 対象記事閲覧 | コンテンツが選択体験へ寄与するか |

公開前には分母を含むイベント仕様を固定する。公開後の基準期間で実測値と端末別・流入別の欠測を確認し、
その値から改善目標を設定する。現時点では転換率の基準値も目標値も未観測である。
