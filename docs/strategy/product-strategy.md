# jidouunten.jp プロダクト戦略

更新: 2026-09-11

市場・競合の根拠: [2026-09-07調査](../research/market-competition-20260907.md)。
JAMAの意向調査とメーカー・在庫検索・専門メディア・NASVAの比較から、初回公開は
日本仕様の販売単位と作動条件の横断比較に集中する。検索量や収益規模は未測定。
車種数より、同じ条件で候補を減らせることと、購入前の根拠確認を価値仮説とする。

初回リリースでGTM/GA4計測、GSC、Bing Webmaster Tools、sitemap登録も扱う。日本向けの初回表示を遮る同意バナーは置かず、計測内容と外部オプトアウト手段をプライバシーページで案内する。
公開後28日またはselector開始100セッションを初回評価の目安とし、未到達でも欠測と実測を報告する。
検索表示・クリック、結果0件率、比較・公式遷移を見て次Sprintを採択する。

## 1. 何を作るか

`jidouunten.jp` は、日本で入手・利用できる自動運転車と運転支援車を、
「レベル」と「実際に使える条件」から選ぶ意思決定ツールにする。

中心となる体験はニュースを読むことではない。利用者が次の問いに答えられることを成果とする。

> 自分の用途と道路環境では、どのレベル・どの車両・どの装備が候補になり、
> 何ができて何ができないのか。

## 2. 主な利用者とJob

| 利用者 | Job | 最初に必要な答え |
|---|---|---|
| 新車購入検討者 | 高速道路や渋滞時の負担を減らせる車を比較したい | 購入可能なLevel 1/2車と作動条件 |
| 先進機能を重視する買替層 | 現在の車より何が進化するか知りたい | ハンズオフ、車線変更、監視方式の差 |
| 自動運転に詳しくない人 | Level 2とLevel 3の違いを誤解なく知りたい | 誰が周囲を監視し、誰が責任を持つか |
| 技術・事業の調査者 | 国内の実用化状況を追いたい | 市販車、移動サービス、実証の区別 |

最初のMVPでは「日本で個人が選べる乗用車」を主対象にする。Level 4/5の移動サービス・実証は、
購入可能な車両と混ぜず別区分で示す。

## 3. 中核導線

```text
レベルを選ぶ
  → そのレベルで可能なこと・運転主体を理解する
  → 購入可能な車両を絞る
  → 道路・速度・監視・装備・価格帯で比較する
  → 公式情報と販売状態を確認して候補を決める
```

トップページ自体を車両一覧・レベル絞り込み画面にする。説明を読んでから別ページへ進むLPは設けない。
初期表示から候補・条件・比較操作に触れられる密度を優先し、基礎解説は必要なときに参照できる補助導線にする。
検索流入した解説やニュースからも、必ず該当レベル・車種の選択画面へ戻す。

## 4. 比較軸

レベルは入口だが、同じレベル内の差を隠さない。最低限、次を比較可能にする。

- 自動化レベルと運転主体
- 対象道路、速度域、天候などのODD（作動設計領域）
- ハンズオフ可否、視線・ドライバー監視、引継ぎ要求
- 車線維持、追従、車線変更、渋滞対応、駐車などの機能
- 必須グレード、メーカーオプション、サブスクリプション
- 日本での販売状態と確認日
- メーカー公式ページ、取扱説明書、国土交通省情報へのリンク

## 5. 信頼設計

- Level 1–2は「運転支援」、Level 3以上を「自動運転」と明記する。
- Level 2では運転者が常時監視することを比較カードと詳細ページで隠さない。
- メーカーの機能名称と自動化レベルを同一視しない。
- 不明は `unknown`、情報が古い場合は `stale` と表示し、推測で補完しない。
- 「搭載あり」ではなく、モデル年・グレード・必要装備・日本仕様まで特定する。
- 安全性の断定や事故回避の保証はしない。購入・使用前に公式説明と取扱説明書の確認を促す。

## 6. コンテンツと集客

ニュースはサブ導線とし、以下のいずれかを満たすものだけ扱う。

1. 車両・グレード・機能・販売状態のデータ更新につながる。
2. 法制度や自動化レベルの理解を更新する。
3. 比較・選択の新しい需要を検証できる。

速報本数やPVだけを目標にしない。記事から関連車両、レベル、比較へ遷移した率を評価する。
恒常的な検索流入は「Level 2 ハンズオフ 車種」「渋滞 自動運転 車」などの選択意図を持つ
解説・比較ページで獲得する。

## 7. 収益仮説

優先順は以下。利用者の判断を歪めないことを前提に検証する。

1. ディーラー・一括見積・中古車在庫への送客
2. 保険、充電、カーリース等の周辺サービス送客
3. 法人向けデータ提供または比較ウィジェット
4. 補助的な広告

広告表示量ではなく、比較完了率、公式・販売先への遷移率、再訪率、送客成果を主要KPIにする。

## 8. MVPと段階展開

### Sprint 1 — Level-first selector

- Level 1/2/3を誤解なく説明する
- 公式一次情報で確認した日本向け車両レコードを最低6件掲載する
- レベル、道路、ハンズオフ可否、販売状態で絞り込める
- 車両詳細で条件、必要装備、分類理由を表示する。根拠URL・確認日は内部管理し、通常UIには表示しない
- 比較対象を2台まで並べられる
- Cloudflare PagesのpreviewでE2E確認し、本番公開可能にする

### 次の段階

- Sprint 2: 用途質問から候補を返すガイドと比較表の深化
- Sprint 3: 更新日・販売状態の監視、差分レビュー、データ鮮度表示
- Sprint 4: 初回に設定した計測の実測を使い、比較完了→公式/販売先遷移のつまずきを改善
- Sprint 5: 車種データに接続する解説・ニュース
- Sprint 6: 利用実績を基に保存比較、通知、Level 4サービスを判断

順番は固定ロードマップではない。GitHub ProjectのReadyキューと実測に基づき更新する。

## 9. 技術方針

- Astro + TypeScript、static-first
- 車両データはGit管理の構造化データ + schema validation
- 絞り込みと比較は初期はクライアント内で完結
- 初回はCloudflare Pages Direct Uploadで公開する。GitHubはソース・Sprintの正本とする。
- 自動配信は次の運用課題。Direct UploadプロジェクトはGit連携へ切替できないため、
  GitHub ActionsからWranglerで配信する方式を優先検討する（専用token・repository secretの設定が必要）。
- フィードバック保存や管理画面が必要になった時点でPages Functions / Workers / D1を検討

Cloudflareは新規アプリではWorkersを主軸に案内しているが、MVPは静的比率が高く、ユーザー希望にも
合うためPagesを採用する。動的要件が増えた時にWorkersへ移れる境界を保つ。

## 10. 成功・失敗の判定

初期KPI:

- selector開始数 / 到達セッション
- 絞り込み完了率
- 比較開始率・比較完了率
- 車両詳細→メーカー公式/販売先クリック率
- 根拠が期限内に確認された車両レコード率

失敗兆候:

- 記事PVは増えるがselector利用が増えない
- 「Level 2だから自動運転」と誤認させる
- 車種名だけでグレード・装備・作動条件が不明
- 更新日がなく、販売終了車と購入可能車が混在する
- データ保守よりニュース量産へ作業が偏る

## 11. 後発に対する防衛線

後発が同じような一覧画面を短期間で作れることを前提にする。防衛線は車種数や記事本数ではなく、
購入判断に使える販売単位データと、その変化を追える履歴を積み上げることに置く。

### 11.1 模倣されにくい資産

- `market + maker + model + model_year + generation + grade + required_package + feature_version`
  を一つの販売単位キーとして維持し、Level・ODD・機能・価格・販売状態・公式導線を同じ正本から結び付ける。
- 価格、機能の追加/削除、作動条件、受注状態の変更を、単なる確認日の更新と区別した差分イベントとして保存する。
- メーカー公式の販売単位へ解決できない候補は「掲載数」に加えず、母集団と欠損理由を内部で管理する。
- 同じ機能名でも責任主体や作動条件が異なる場合は、共通ラベルへ潰さず条件付きの能力語彙として保持する。

### 11.2 利用者が戻ってくる理由

保存した候補・比較・検索条件に対して、意味のある価格/機能/販売状態の差分だけを次回来訪時に示す。
「更新があった」だけの通知や通知数の最大化は行わない。保存機能はまずログイン不要の同一ブラウザMVPで検証し、
利用実績が得られてから同期・通知を判断する（#18）。

2026-09-11の再訪MVPでは、保存時点の販売単位ごとに公開判断材料のfingerprintを保持する。
確認日・出典URLだけの差し替えはfingerprintを変えず、価格、機能、作動条件、必要装備、販売状態、
グレード識別に関わる変更だけを次回来訪時の「判断材料の変更」として示す。これは変更通知を量産する仕組みではなく、
比較を再開する前に何を見直すべきかを知らせるための最小実装である。

### 11.3 競争優位を測る指標

件数・記事PV・通知数を堀の成果としない。次を内部の品質指標として追う。

- 主要販売単位のカバー率（分母と未掲載理由を定義したうえで計測）
- 価格/機能/販売状態の意味ある差分を、対象ページと履歴へ反映できた割合
- 保存した候補・条件からの再訪率と、再訪後の比較/公式遷移率
- 公式一次情報へ解決できる販売単位の割合と、期限内に再確認できた割合

これらが改善しないままニュースや比較URLだけを増やす施策は、後発対策ではなく保守負債として扱う。

### 11.4 直近の実装で証明する堀

RAV4を4販売単位（Z HEV、Z PHEV、Adventure HEV、GR SPORT PHEV）へ分け、同じLevel 2でも
価格・パワートレーン・ドライバーモニター標準／オプション・LCA／Advanced Driveの差を比較できるようにした。
ベース価格にオプションを混ぜず、ハンズオフ可能と数えるのは装備が標準または価格と条件を固定できた販売単位だけに限定する。
この「同一モデル内の差分を公式資料で再現できる」状態を、Toyota/Lexusの未掲載候補へ横展開することが、後発が名称とLevelラベルだけを模倣しても追いつけない最初の実データ資産になる。
次の実装トランシェではハリアーHEVの6販売単位（G/Z/Z“Leather Package”の2WD・E-Four）を追加し、価格・駆動方式・ACC/LTA・停止保持・ハンドル保持要求を同一画面で比較できるようにした。根拠がないLCAやドライバーモニターを付けない判断も、後発が機能名だけを横並びにする場合との差分になる。

### 11.5 比較差分で証明する堀（2026-09-10）

比較画面は、価格・Level・道路・速度・ハンズオフ・運転者監視・必要パッケージ・販売状態を意味単位で判定し、既知の差だけを強調する。同値行は任意で隠せるが、`unknown` は差分にも優劣にも変換せず常時明示する。確認できた機能は日本語ラベルで販売単位へ結び付け、機能の不在を未確認のまま「なし」と断定しない。Tesla Model 3 Premium × Model Y Premiumの実ブラウザで、差分1行・同値9行・未確認2行を確認した。この比較契約は後発がLevel 2の数値や機能名だけを模倣する場合に対する、根拠付き差分データの蓄積面となる。

### 11.6 購入判断の出口で証明する堀（2026-09-10）

候補を並べるだけでなく、一次情報で確認できた販売単位だけに「今すぐ注文」「試乗を予約する」などの次アクションを表示し、クリックを購入判断の出口として計測する。Tesla Model 3 / Model Yで詳細6販売単位（各2導線）と2台比較（4導線）を本番確認した。公式商品情報への遷移と、注文・試乗への遷移は別イベントで保持するため、後発がボタン文言だけを模倣しても、どの販売単位・どの確認日・どの公式URLから送客したかを再現できる。

この堀は「全メーカーに導線がある」と見せることではない。一次情報で注文可否を断定できないToyota/Lexus等は無理にCTAを付けず、確認待ちのまま残す。今後はメーカーごとの公式注文・試乗・販売店導線を同じ販売単位キーへ解決し、リンク切れ・受注状態変更を履歴として検知できる範囲を広げる（#25, #37）。

### 11.7 後発が追いつきにくい販売単位カバレッジ（2026-09-10）

アルファード4単位（Z/G HEV、2WD/E-Four、7/8人乗り）とVEZEL e:HEV Z 2単位（FF/4WD）を追加し、公開候補を現行100販売単位へ拡張した。その後ヴェルファイア7単位、ヴォクシー6単位、シエンタ18単位、Lexus LM2単位、UX300h 6単位を加え、現行139販売単位まで広げた。さらにノアを現行HEV全8単位へ展開し、現行146販売単位とした。単に車名を増やしたのではなく、価格・駆動方式・乗車定員・支援機能・作動速度・ハンズオフ条件を同じ比較キーへ固定している。後発が「Level 2」「ACC搭載」といった名称だけを模写しても、同一モデル内の購入候補差と、どの条件が未確認なのかを再現するには、この販売単位台帳と一次情報の再確認履歴が必要になる。

この差は未確認を減らすことだけでなく、確認できないものを誤って「注文可」「ハンズオフ可」と表示しないことにもある。アルファードとVEZELは公式掲載・価格・機能を確認したが販売単位ごとの注文可否を固定できないため、CTAを付けず`unknown`として公開した。正確さを保ったままカバレッジを増やすことを、後発対策の品質基準とする。

### 11.8 比較の意思決定速度とオプション総額で深掘る（2026-09-10）

後発が同じ車名・Level・機能ラベルを揃えても、利用者が「この2台の差」を数秒で確認できなければ選択サービスとしての価値は残らない。比較URLでは選択フォームを折り畳み、結果を先頭に表示し、変更時だけフォームを開く。比較行は「不明」を既知の差として強調せず、確認できた追加パッケージ価格は車両本体価格と分離して表示する。これにより、CX-5 GとG（EX Package）のように、ハンズオフ機能へ進むための追加費用を推測なしで比較できる。

同様に、MINI Countrymanの高速道路渋滞時ハンズオフ対応6販売単位は、説明文だけでなく道路フィルターにも反映した。一次資料の細部を「一覧の絞り込み」「比較表」「次アクション」まで一貫させ、未確認は未確認のまま残す。この一貫性と意思決定までの到達時間を、後発対策の実測指標（比較結果の到達率、公式遷移率、オプション価格の確認率）として追う（#2, #23, #24）。

### 11.9 電動化・定員・駆動方式を含むミニバン比較の深掘り（2026-09-10）

ヴェルファイアではExecutive Lounge（PHEV/HEV）とZ Premier（HEV/ターボガソリン）を、駆動方式と乗車定員を分けた7販売単位として登録した。全単位でACC・LTA・LCA・アドバンスト ドライブ（渋滞時支援）とドライバーモニターを同じ正本に結び付け、価格帯674万9,600円〜1,089万9,900円、渋滞時0〜約40km/hの条件付きハンズオフとして比較できる。これにより、後発が「ミニバン」「Level 2」「ハンズオフ可」とだけ表示しても、PHEVとガソリン、6人と7人、2WDと4WDの選択理由と条件差を再現できない状態を避ける。

注文可否は公式商品ページの掲載だけでは断定せず、7単位とも`unknown`のまま公式CTAを表示しない。確認できた事実だけを比較へ積み上げ、未確認の受注状態を混ぜないこと自体を信頼性の堀とする。次は同じ粒度でLexus UX／LMなどの候補を調査し、主要モデル分母と公式注文・試乗導線を解決できた単位から拡張する（#17, #25, #37）。

### 11.10 ヴォクシーで「グレード×定員×オプション総額」を固定する（2026-09-10）

ヴォクシーをS-Z/S-Gの2WD・E-Four、7/8人乗り、S-GベースのMULTI UTILITY 5人乗りまで6販売単位へ分解した。車両本体価格は375万1,000円〜438万200円で、条件付きハンズオフへ進むAdvanced Drive・LCA・ドライバーモニターカメラのセット価格はS-Zが12万2,100円、S-Gが7万8,100円。ACC・LTA標準と、Advanced Driveの渋滞時0〜約40km/h、LCA約85〜130km/hを同じ販売単位に結び付け、ベース価格と追加パッケージを分けて表示する。

これにより、後発が「ミニバン」「Level 2」「ハンズオフ可」というラベルだけを模倣しても、2WD/E-Four、5/7/8人、S-Z/S-Gの価格差、メーカーオプションの追加費用、支援速度の差を一度に再現しにくい。装着時のみ条件付きハンズオフとして扱い、新車注文可否は6単位とも`unknown`のままCTAを出さない。今後も同じモデル内の装備差を、公式資料で固定できた範囲だけ追加する。

### 11.11 シエンタで「低価格帯×18組み合わせ」の後発耐性を作る（2026-09-10）

シエンタはZ/G/X、ハイブリッド車／ガソリン車、2WD／E-Four、5人乗り／7人乗りの全18組み合わせを公式グレードJSONから登録した。価格は214万6,100円〜339万7,900円で、ミニバンの入口価格から上位グレードまで、同じLevel 2でも動力・駆動・定員による選択を一覧で絞り込める。全車速ACCとLTAは標準の運転支援だが、ステアリング保持が必要でハンズオフ不可。LCAやドライバーモニターの根拠がないため能力を足していない。
